## 1. 项目背景与目标（增量补充）

v1.0.0 已实现 Python 脚本集中化管理与服务监控。随着业务进一步扩展，运营/数仓团队提出：

- 大量「数据校验、对账、报表巡检」类逻辑以 **SQL** 形式存在，目前散落在各种调度系统配置或文档中，缺乏统一管理；
- Python 与 SQL 脚本都希望在保存前**先在线试跑一次**，确认无语法/结构错误再下发；
- 现有 Python 告警字段较粗（仅钉钉 + 电话），缺少 **告警等级、日志来源、通知模板、通知群** 等关键维度，无法对接公司统一告警平台。

### 1.1 v1.1.0 目标

1. 在保留 Python 脚本管理体验的同时，**新增对等的 SQL 脚本管理模块**；
2. 提供 **在线试跑（测试运行）** 能力，覆盖 Python 与 SQL 两类脚本；
3. **完善告警元信息**：等级、日志来源、模板、通知群，与下游告警平台对接；
4. 不破坏 v1.0.0 现有数据，提供平滑升级方案。

### 4.2 Python 脚本管理模块（增量调整）

| `alert_template` | varchar(128) | ❌ | 通知模板标识（与下游告警平台模板编号对齐） |
| `alert_group` | varchar(128) | ❌ | 通知群标识（钉钉群名 / 群 ID） |

> 其余字段（`script_name`、`script_path`、`module`、`description`、`owner`、`alert_dingtalk`、`alert_phone`、`schedule_cron`、`schedule_desc`、`script_content`、`version`、`status` 等）保持 v1.0.0 不变。

#### 4.2.2 列表页变化

- 列表新增 1 列「告警等级」（`alert_level`），用 Tag 颜色区分：L1 红 / L2 橙 / L3 蓝；为空时显示 `—`。
- 搜索条件区新增「告警等级」下拉筛选（多选）。
- 其余列与 v1.0.0 一致。

#### 4.2.3 编辑页变化

- 表单中 **"告警通道"** 分组扩充为：
  - 钉钉 Webhook（原有）
  - 预警电话（原有）
  - 告警等级（Select：L1 / L2 / L3）
  - 告警日志来源（Input）
  - 通知模板（Select 或 Input，下拉数据来自 `sys_config.alert_template_list`，可后台扩展）
  - 通知群（Input）
- 校验：`alert_level` 设置为 L1 时，**必须**至少配置一种通知渠道（钉钉 / 电话 / 群），否则保存校验失败。

#### 4.2.4 测试运行（v1.1.0 新增）

**入口**：编辑页与查看页右上角新增 `【测试运行】` 按钮（仅 admin 及以上可见）。

**交互**：

1. 点击按钮后弹出测试结果抽屉（右侧 60% 宽，底部固定 ‹关闭› ‹再次运行›）；
2. 顶部展示「执行中…」状态条 + 实时秒表；
3. 后端将当前编辑器 buffer（未保存内容）写入临时文件 `/tmp/scriptplatform/python_test_<id>_<ts>.py`；
4. 通过 `ProcessBuilder` 执行 `python3 /tmp/.../xxx.py`，捕获 stdout / stderr / 退出码；
5. 默认超时 **30 秒**（可由 `script.test.python.timeout-sec` 配置），超时强制 kill 并标记失败；
6. 返回结果展示：
   - 顶部状态徽标：绿色「执行成功」 / 红色「执行失败」 / 灰色「超时终止」
   - 退出码、耗时（毫秒）
   - **stdout**（默认折叠展开，等宽字体）
   - **stderr**（红色高亮）
7. 临时文件在执行结束后立刻删除。

**安全约束**：

- 单进程内存上限 256MB（`ulimit -v`），防止失控脚本拖垮主机；
- 进程以专用低权限系统账号 `scriptrunner` 运行；
- 不允许网络出站到内网管理面（通过宿主网络策略约束，非应用层）；
- 同一用户同一脚本同时只允许 1 个测试任务（按 `monitor_id + operator` 加 Redis/内存锁）。

**审计**：每次测试写一条 `PYTHON_TEST` 审计记录，含脚本 ID、操作人、是否成功、耗时；不记录 stdout/stderr 内容（避免敏感数据泄露）。

#### 4.2.5 保存逻辑（沿用 v1.0.0 + 明确化）

- 保存前对 `python_script_info.version` 做乐观锁校验（请求体携带 `version`，与 DB 不一致则返回 409）；
- 保存动作：
  1. DB 写入：版本号 +1，记录 `updated_at` / `operator`；
  2. 文件落盘：以 `script_path` 为目标，**先备份**为 `script_path + ".bak." + yyyyMMddHHmmss"`，再覆盖写入；
  3. 写审计日志 `PYTHON_UPDATE` / `PYTHON_CREATE`。

#### 4.3.6 测试运行（SQL）

**入口**：编辑页与查看页 `【测试运行】` 按钮（admin 及以上可见）。

**配置**：平台维护一个 **专用测试数据源**（`spring.datasource.sql-test.*`），要求：
- 只读账号（建议 DB 层授予 `SELECT` 权限）；
- 与生产同库结构（建议是从库快照或独立测试库）；
- 在 `application.yml` 中配置；不可与平台主库共用。

**交互**：

1. 点击后弹出测试抽屉（右侧 70% 宽）；
2. 抽屉顶部展示：使用的数据源标识（脱敏，仅显示别名）、最大返回行数（默认 100，用户可在 1~1000 间调整）、超时时间（30s 固定）；
3. 后端处理流程：
   - **SQL 安全解析**：使用 JSqlParser 解析 SQL；只允许单条语句，且类型必须为 `SELECT`；其他语句类型（INSERT / UPDATE / DELETE / DROP / ALTER / TRUNCATE / CREATE / GRANT 等）一律拒绝并返回 `400 SQL 类型不允许测试，仅支持 SELECT`；
   - **强制 LIMIT**：如解析后未带 LIMIT 子句，自动包装为 `SELECT * FROM (<original sql>) _t LIMIT N`；如已有 LIMIT，取 `min(原 LIMIT, N)`；
   - 通过 `JdbcTemplate` 在测试数据源上执行，`queryTimeout = 30s`；
   - 整个执行包在事务中并最终 `rollback`，作为额外保险（即使误放过非 SELECT 也不会落库）；
4. 返回结果展示：
   - 状态徽标：成功 / 失败 / 超时；
   - 耗时（ms）、返回行数；
   - **结果表**：分页表格展示 columns + rows；超过 50 列时折叠超出列；NULL 渲染为灰色 `NULL`；
   - **错误信息**：若失败，红色文本展示 `SQLException` 的 `errorCode` + `state` + `message`；
   - 顶部按钮：`【导出 CSV】`（限本次结果集）、`【再次运行】`、`【关闭】`。

**审计**：每次测试写一条 `SQL_TEST` 审计记录，包含脚本 ID、操作人、是否成功、行数、耗时；不记录 SQL 全文（已存在 `target_id`，可关联回查）和返回数据。

**性能**：单实例同时执行的 SQL 测试数 ≤ 5（`ThreadPoolTaskExecutor` 限流），超出排队等待；超过 1 分钟仍未排到则返回 `429 测试任务排队拥挤，请稍后再试`。

#### 4.3.7 删除 SQL 脚本

- 二次确认弹窗：「确认删除 SQL 脚本 `{sql_name}`？此操作不可撤销。」
- 删除后写 `SQL_DELETE` 审计；DB 物理删除（不做软删除，与 Python 一致）。

## 6. 数据库表结构设计（增量）

### 6.1 Python 脚本表（v1.0.0 表更名 + 字段扩展）

**重命名**：`script_info` → `python_script_info`

```sql
-- 6.1 Python 脚本配置表
CREATE TABLE `python_script_info` (
  `id`               BIGINT        NOT NULL AUTO_INCREMENT COMMENT '主键',
  `script_name`      VARCHAR(128)  NOT NULL COMMENT '脚本名称',
  `script_path`      VARCHAR(512)  NOT NULL COMMENT '脚本路径',
  `module`           VARCHAR(64)   NOT NULL COMMENT '归属模块',
  `description`      TEXT          COMMENT '功能说明',
  `owner`            VARCHAR(64)   NOT NULL COMMENT '负责人',
  `alert_dingtalk`   VARCHAR(256)  DEFAULT NULL COMMENT '预警钉钉',
```

## 12. 风险与约束

| 风险 | 影响 | 应对 |
| ---- | ---- | ---- |
| Python 测试脚本运行环境差异（依赖包） | 测试结果与生产不一致 | 测试运行使用与生产对齐的虚拟环境镜像；显式声明使用的解释器版本 |
| 恶意脚本逃逸 | 主机被入侵 | 专用低权限账号、`ulimit` 限制、超时 kill、禁止内网管理面访问；后续可上容器化沙箱 |
| SQL 测试数据源被误用为生产库 | 误执行带来数据风险 | 部署清单中强制只读账号 + 启动自检（执行 `SELECT @@global.read_only`，非只读则拒启动） |
| SQL 测试拖垮测试库 | 测试库 CPU 飙升 | 限并发 5；queryTimeout 30s；建议使用从库或独立测试集群 |
| 前端 Monaco SQL 自动补全词表过时 | 用户体验差 | 词表来自 `sys_config.sql_keywords`，可后台维护，每次刷新拉取 |
| 旧路径兼容期被滥用 | 路径混乱 | 在响应头加 `Deprecation: true` + `Sunset` 时间，文档同步标注 |
